## 1. 目的と範囲

社内で受けた電話の対応を支える Web システム。

- 電話番号を入力すると、すでに「迷惑番号」として登録されているかを、自動で確認する（登録フォームの中で）
- 迷惑でなければ、電話の伝言を登録し、Teams のチャネルへメールで通知する
- 迷惑だったときは、迷惑番号として登録し、着信を記録する
- 受けた伝言を、一覧で見る・削除する

範囲外（作らないもの）: ログイン・権限管理、Teams でのメンション、伝言の編集、過去データの自動削除。

## 2. 業務の流れ

```
電話を受ける
  └ 登録フォームの「電話番号」に入力（自動で、迷惑番号か確認）
       ├ 迷惑番号に登録されている → 赤い札とカード。着信を記録する（対応者・メモ）
       └ 登録なし
            ├ 通常の電話 → 伝言を入力 →「このまま伝言を登録する」（確認画面なし）→ 伝言一覧へ → Teams に通知
            │             （確認してから登録したいときは、「確認」→「最終OK」）
            └ 迷惑電話だった → 「迷惑番号として登録する」→ その場で、会社名・メモを入れて登録（着信も1件、記録）
```

画面上部の矢印のタブは、この順（登録フォーム → 伝言一覧 → 迷惑番号一覧）に並ぶ。

## 4. 画面

共通: 上に矢印のタブ（登録の途中の「確認」「完了」では出さない）。スマホ幅（390px）で横にはみ出さない。

| 画面 | パス | 内容 |
|---|---|---|
| （最初の画面） | `/` | `/register` へ移動する |
| 迷惑番号一覧 | `/nuisance/list`（`/nuisance` は、登録フォームへ移動） | 登録済みの迷惑番号を、折り畳みのカードで一覧。絞り込み、新規登録、編集、削除 |
| 登録フォーム | `/register` | 電話番号（任意。入力すると、迷惑番号か自動で確認）、電話先（任意）、伝言内容、自分の名前、伝言先を入力 |
| 確認 | `/confirm` | 入力内容を、電話先・伝言内容・受電者・伝言先に分けて表示。「修正する」「最終OK」 |
| 完了 | `/complete` | 登録した旨と、環境に応じた通知の文言 |
| 伝言一覧 | `/list` | 伝言をメモ形式のカードで一覧（新しい順、最大50件）。キーワード絞り込み、削除 |
| 伝言詳細 | `/detail/:messageId` | 1件の全文。受電者、電話先、日時 |

### 4.1 登録フォームの、迷惑番号の自動チェック（`/register`）

- 入力: 電話番号（任意）。全角、ハイフンの有無、`+81` 付きでも同じ番号として扱う。画面を開いたとき、この欄にカーソルがある。
- 確認のタイミング: 8桁以上になって、入力が0.5秒止まったとき。入力のたびには確認しない。確認中は「迷惑番号か確認しています…」。
- 結果「登録されています」: 赤い札と、迷惑番号のカード（閉じた状態。電話番号と会社名だけ）。カードを開くと、メモ・着信ログの確認と、「今回の着信を記録する」（対応者・メモ）ができる。登録されていても、伝言の登録は続けられる。
- 結果「登録なし」: 緑の「✓ 〇〇 は、迷惑番号には登録されていません」と、次の2つのボタン。どちらも、画面を移らずに、その場で行う。
  - 「このまま伝言を登録する」: 確認画面と完了画面を飛ばして、伝言を登録し、**伝言一覧**へ移る。必須の項目（伝言内容・自分の名前・伝言先）が空のときは、ボタンの下に、足りない項目を知らせて、登録しない。登録に失敗したときは、「伝言を登録できませんでした。もう一度お試しください」と出て、入力は残る。
  - 「迷惑番号として登録する」: 会社名（登録フォームの電話先が入る）とメモの小さなフォームが開く。「登録する」で、迷惑番号に登録し、着信も1件、記録する（対応者は、自分の名前）。登録後は、その番号が、赤い札とカードで出る。
- 確認に失敗したとき: エラーの文言（登録フォームの入力は続けられる）。
- 入力した電話番号は、伝言の本文の最後に「TEL：番号」の1行として加える（本文に同じ番号がすでにあれば、加えない）。確認画面で、「修正する」を押しても、電話番号は残る。

### 4.2 迷惑番号のカード（検索結果と一覧で共通）

- 閉じた状態: 電話番号と会社名だけ（会社名がないときは「（会社名不明）」）。
- 開いた状態: 着信回数、最終着信、メモ、着信ログ（新しい5件まで、残りは「ほかN件」）、対応者とメモの入力欄、「今回の着信を記録する」。一覧では、「編集」「削除」（ゴミ箱）も出る。

### 4.3 迷惑番号一覧（`/nuisance/list`）

- 並び順: 最終着信が新しい順（着信がないものは、登録日時）。
- 絞り込み: 番号・会社名・メモ。
- 新規登録: 電話番号（必須、重複不可）、会社名・メモ（任意）、「今回の着信としてログに記録する」。
- 編集: 会社名とメモ（番号は変更できない）。
- 削除: 確認ダイアログのあと、削除。
- 取得に失敗したとき: 「一覧の取得に失敗しました。もう一度お試しください」。

### 4.4 登録フォーム → 確認 → 完了

- 電話番号の自動チェックと、確認を通らない直接の登録は、4.1。確認を通る登録（「確認」→「最終OK」）も、そのまま使える。
- 必須: 伝言内容、自分の名前（受電者）、伝言先。未入力のとき、「伝言内容を入力してください」「自分の名前を入力してください」「伝言先を選択してください」。
- 電話先（企業名）は専用項目がなく、伝言内容の先頭に `【電話先】企業名` の1行として保存する。画面で取り出して表示する。
- 自分の名前は、そのブラウザに覚える（次回から選択済み）。
- 完了画面の文言: 本番「Teamsへ通知しました。」＋Teams チャネルへのリンク／テスト「テスト用チャネル（99_テスト）へ通知しました。」／仮データ「テストモードのため、Teamsには通知していません。」

### 4.5 伝言一覧・詳細

- 「このまま伝言を登録する」で登録した直後は、一覧の上に、「〇〇 宛の伝言を登録しました。」と、通知についての文言（本番「Teamsへ通知しました。」／テスト「テスト用チャネル（99_テスト）へ通知しました。」／仮データ「テストモードのため、Teamsには通知していません。」）が出る。登録した伝言が、いちばん上に出る。
- 一覧: 1件の枠の高さは一定。電話先は1行、内容は2行までで、あふれた分は「…」。電話先がないときは「（電話先なし）」。枠（電話先・内容の部分、または宛先）をクリックすると詳細へ。
- 削除: ゴミ箱のボタン、確認ダイアログ「この伝言を削除しますか？」。
- 詳細: 伝言先、日時、電話先、伝言内容（改行をそのまま）、受電者。

## 5. API

ベース URL は環境ごとに異なる（`api.ts` の本番 URL、テストは `terraform-test` の出力 `api_url`）。形式は JSON。認証はない。

### 5.1 伝言（既存）

エラーのときも HTTP 200 で、文字列を返すものがある（既知の制約。7章）。

| メソッド・パス | 内容 | 成功時 | 失敗時 |
|---|---|---|---|
| `GET /members` | 社員一覧（伝言先に使われた回数が多い順） | `[{memberId, memberName, displayName?}]` | — |
| `GET /messages` | 伝言一覧（新しい順、最大50件） | `[{messageId, messageBody, receiverName, destination, registeredAt}]` | — |
| `GET /messages/{messageId}` | 伝言1件 | 上と同じ形のオブジェクト | `NOT_FOUND`（文字列） |
| `POST /messages` | 伝言の登録とメール通知 | `SUCCESS`（文字列） | 例外名と内容の文字列 |
| `DELETE /messages?messageId=` | 伝言の削除 | `SUCCESS` | `messageId is required` など |

`POST /messages` の本文: `{messageBody, receiverName, destination}`。`registeredAt` は日本時間の `yyyy/MM/dd HH:mm:ss`。

### 5.2 迷惑番号（新規。正しい HTTP ステータスを返す）

| メソッド・パス | 内容 | 成功 | 失敗 |
|---|---|---|---|
| `GET /nuisance` | 一覧 | 200 `[迷惑番号]` | 500 |
| `GET /nuisance/{phoneNumber}` | 1件（検索） | 200 迷惑番号 | 404 登録されていません |
| `POST /nuisance` | 登録。本文 `{phoneNumber, companyName, memo, recordCall, receiverName}` | 201 迷惑番号 | 400 桁数、409 重複 |
| `PUT /nuisance/{phoneNumber}` | 編集。本文 `{companyName, memo}` | 200 迷惑番号 | 404 |
| `DELETE /nuisance/{phoneNumber}` | 削除 | 200 `{"message":"deleted"}` | — |
| `POST /nuisance/{phoneNumber}/logs` | 着信ログの追加。本文 `{receiverName, note}` | 200 迷惑番号 | 404 |

- 電話番号は、サーバー側でも整える（全角→半角、数字以外を除く、先頭の `+81` を `0` に）。8〜15桁の数字でなければ 400「電話番号の桁数を確認してください」。
- 迷惑番号の形: `{phoneNumber, companyName, memo, registeredAt, logs: [{calledAt, receiverName, note}]}`。

## 6. データ（DynamoDB、課金は使った分だけ）

| テーブル | キー | 項目 |
|---|---|---|
| `Messages` | `messageId`（UUID） | messageBody, receiverName, destination, registeredAt |
| `Members` | `memberId` | memberName, displayName（任意）, fromEmail（任意） |
| `NuisanceNumbers`（新規） | `phoneNumber`（数字だけ） | companyName, memo, registeredAt, logs（calledAt, receiverName, note の一覧） |

- テスト環境のテーブル名は `Messages-test`、`Members-test`、`NuisanceNumbers-test`。Lambda の環境変数 `MESSAGES_TABLE`・`MEMBERS_TABLE`・`NUISANCE_TABLE` で切り替える（未設定なら、本番の名前）。
- `Members`（社員一覧）は、画面では編集できない。AWS コンソールの DynamoDB で直接編集する。

## 7. 通知

- 伝言の登録時、Lambda が Amazon SES でメールを送り、Teams チャネルのメールアドレスに届く。
- 差出人: 受電者に対応する `Members.fromEmail`、なければ環境変数 `FROM_EMAIL`。SES で検証済みのアドレスだけ使える。
- 宛先: 環境変数 `TEAMS_EMAIL`（本番は `c9453f82…`、テストは `371a9bd5…`）。
- Teams のチャネルには、メールを受け付けるドメインの許可リストがある。差出人のドメインが許可リストにないと、AWS は送信に成功しても、Teams には届かない。
- 迷惑番号の登録・記録は、Teams に通知しない。

## 8. 非機能

- **アクセシビリティ:** 文字と背景のコントラスト比は、基準の 4.5:1 以上を目標にした（色の値から計算）。キーボード操作の目印（フォーカスの枠）あり。タッチ画面では、押す部品の高さを 44px 以上。動きを減らす設定の人には、動きを止める。ページの言語は日本語（`ja`）。
- **対応する画面幅:** パソコン幅〜スマホ幅（390px で確認）。
- **ブラウザ:** 最新の Chrome 系で確認。他のブラウザは未確認。
- **性能:** 一覧は全件をスキャンして取得する（`Messages` は最大50件を返す）。件数が増えると遅くなる。
