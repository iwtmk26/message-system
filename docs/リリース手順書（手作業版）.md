**この手順書の基本の方針**

- 既存の資源（`Messages`・`Members`・既存の5ルート・通知の設定）は、**触らない**。足すのは、表1つ、ルート6本、環境変数1つ、CORS の `PUT`、新しい jar、新しい画面だけ。
- **変更の前に、必ず、今の状態を記録して、バックアップを取る。** 戻せなくなる操作は、しない。
- 1つずつ、確認してから、次へ進む。
- 秘密の値（通知の宛先、差出人のアドレスなど）は、この文書にも、記録にも、書かない。名前（変数名）だけを控える。

表記: コマンドは、PowerShell で、1つずつ実行する。`<…>` は、自分の値に、置き換える。プロファイル `shift-prod`、リージョン `ap-northeast-1`（東京）。AWS コンソールは、右上を「東京」にする。

## 2. 変更（API 側）

### 2.1 DynamoDB の表 `NuisanceNumbers` を作る

```
aws dynamodb create-table --table-name NuisanceNumbers --attribute-definitions AttributeName=phoneNumber,AttributeType=S --key-schema AttributeName=phoneNumber,KeyType=HASH --billing-mode PAY_PER_REQUEST --profile shift-prod --region ap-northeast-1
```

```
aws dynamodb wait table-exists --table-name NuisanceNumbers --profile shift-prod --region ap-northeast-1
```

- [ ] コンソールで、`NuisanceNumbers` が、「アクティブ」になった

### 2.2 実行ロールの権限

1.5 で、既存の許可が、**すべての表**、または、`NuisanceNumbers` を含む指定なら、このステップは、不要。

表の名前を、個別に指定していて、`NuisanceNumbers` が、入っていなければ、ロールに、次の**インラインポリシー**を足す（名前: `NuisanceNumbersAccess`）。`<アカウントID>` は、自分の値に。

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "dynamodb:GetItem",
        "dynamodb:PutItem",
        "dynamodb:UpdateItem",
        "dynamodb:DeleteItem",
        "dynamodb:Scan"
      ],
      "Resource": "arn:aws:dynamodb:ap-northeast-1:<アカウントID>:table/NuisanceNumbers"
    }
  ]
}
```

- [ ] 権限が、足りた（足りないと、迷惑番号の画面で、エラーになる。6章で見つかる）

### 2.3 Lambda の環境変数を、1つ足す

**コマンドではなく、コンソールで行う**（コマンドの更新は、既存の変数を、すべて置き換えてしまう）。

- [ ] Lambda → `message-api-tf` → 「設定」→「環境変数」→「編集」→「環境変数の追加」
- [ ] キー `NUISANCE_TABLE`、値 `NuisanceNumbers` を足す。**既存の変数は、触らない**
- [ ] 保存。保存後、変数の**名前**の数が、1つ増えただけ（1.1 で控えた名前が、すべて残っている）ことを確認する

### 2.4 Lambda のコードを、新しい jar に入れ替えて、新しいバージョンを公開する

- [ ] 最新の jar を作る（`main` にマージされた、リリース用のコミットで）。

```
cd C:\dev\message-system\backend\message-api
```

```
mvn package
```

`target\message-api-1.0-SNAPSHOT.jar` ができる。「BUILD SUCCESS」、テストが通ったことを確認。

- [ ] コードを入れ替えて、新しいバージョンを公開する（コマンド）。

```
aws lambda update-function-code --function-name message-api-tf --zip-file fileb://C:\dev\message-system\backend\message-api\target\message-api-1.0-SNAPSHOT.jar --publish --profile shift-prod --region ap-northeast-1
```

（コンソールで行う場合: 「コード」→「アップロード元」→「.zip または .jar ファイル」→ jar を選んで保存 →「バージョン」→「新しいバージョンを発行」）

- [ ] 出力の `Version` と `LastUpdateStatus`（`Successful`）を、控える
- [ ] **API Gateway の統合が、公開したバージョン（またはエイリアス）を指しているか**を、1.1 の記録と、見比べる。**`$LATEST` を指しているなら、公開しなくても、新しいコードが、使われる**。バージョンやエイリアスを指しているなら、統合の ARN を、新しいバージョンに、更新する必要がある（更新しないと、新しいコードが、使われない）

### 2.5 API Gateway に、ルートを6本、足す

統合の ID（1.2 で控えたもの）を、使う。1本ずつ、実行して、「RouteId」が返ることを確認する。

```
aws apigatewayv2 create-route --api-id <API_ID> --route-key "GET /nuisance" --target integrations/<統合のID> --profile shift-prod --region ap-northeast-1
```

```
aws apigatewayv2 create-route --api-id <API_ID> --route-key "GET /nuisance/{phoneNumber}" --target integrations/<統合のID> --profile shift-prod --region ap-northeast-1
```

```
aws apigatewayv2 create-route --api-id <API_ID> --route-key "POST /nuisance" --target integrations/<統合のID> --profile shift-prod --region ap-northeast-1
```

```
aws apigatewayv2 create-route --api-id <API_ID> --route-key "PUT /nuisance/{phoneNumber}" --target integrations/<統合のID> --profile shift-prod --region ap-northeast-1
```

```
aws apigatewayv2 create-route --api-id <API_ID> --route-key "DELETE /nuisance/{phoneNumber}" --target integrations/<統合のID> --profile shift-prod --region ap-northeast-1
```

```
aws apigatewayv2 create-route --api-id <API_ID> --route-key "POST /nuisance/{phoneNumber}/logs" --target integrations/<統合のID> --profile shift-prod --region ap-northeast-1
```

- [ ] ルートの一覧に、既存の5本（`GET /members`、`GET /messages`、`GET /messages/{messageId}`、`DELETE /messages`、`POST /messages`）と、新しい6本が、すべて、ある
- [ ] 既存の Lambda の呼び出し許可（API Gateway → Lambda）が、`*/*` を許す形なので、新しいルートにも、効く（効かないと、新しいルートが、500 になる。6章で見つかる）
- [ ] ステージ `$default` が、自動デプロイ（auto deploy）か、確認する（そうでなければ、デプロイを実行する）

### 2.6 CORS に `PUT` を足す

**コンソールで行う**（コマンドの更新は、設定を、丸ごと置き換える）。

- [ ] API Gateway → `message-api-tf` → 「CORS」→「設定」。許可するメソッドに、`PUT` を足す。ほかは、変えない（許可するオリジン、ヘッダー、max-age）

### 2.7 API 側の動作確認（画面を置く前に）

本番の API の URL を、`<本番API>` とする。**本番のデータを増やさない確認**だけを行う。

- [ ] 結果が、`[]` と `[200]`（空の一覧）

| 症状 | 戻し方 |
|---|---|
| 画面がおかしい | 1.4 で保存した画面を、S3 に戻す（`aws s3 sync C:\dev\backup\<日付>\frontend s3://message-system-frontend --delete`）。CloudFront のキャッシュを、消す |
