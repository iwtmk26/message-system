## 5. リリースの手順

**順番: API → 画面。** 新しい API は、古い画面とも両立する（新しいルートが増えるだけ）ので、API を先に入れる。

### 5.1 API（Lambda・表・ルート）

1. jar を作る。

   ```
   cd C:\dev\message-system\backend\message-api
   ```

   ```
   mvn package
   ```

   `target/message-api-1.0-SNAPSHOT.jar` ができる（約17MB）。

2. 本番の Terraform の変更（3章）を、`terraform/main.tf` に反映する。
3. 差分を確認する。

   ```
   cd C:\dev\message-system\terraform
   ```

   ```
   $env:AWS_PROFILE = "shift-prod"
   ```

   ```
   terraform plan
   ```

   **確認すること:** 追加は、表1・ルート6・（環境変数と CORS の変更）・Lambda の更新だけ。**削除（destroy）や、`Messages`・`Members` の変更が出たら、実行しない。**

4. 反映する（担当者）。

   ```
   terraform apply
   ```

   「Plan: … to add, … to change, 0 to destroy」を確認して、`yes` と入力する。

### 5.2 画面（S3・CloudFront）— **要確認（推測の手順）**

1. 画面をビルドする。**本番ビルドは、`.env.development.local` の影響を受けない**（本番の API に必ず接続する）。

   ```
   cd C:\dev\message-system\frontend
   ```

   ```
   npm run build
   ```

   `dist/` ができる。

2. `dist/assets/*.js` に、本番の API の URL が入り、テスト用の URL が入っていないことを確認する（テスト項目 H04）。
3. S3 に置く。

   ```
   aws s3 sync dist s3://message-system-frontend --delete
   ```

4. CloudFront のキャッシュを消す（ディストリビューション ID は、**要確認**）。

   ```
   aws cloudfront create-invalidation --distribution-id <ID> --paths "/*"
   ```
